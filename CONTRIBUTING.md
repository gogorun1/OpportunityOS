# Contributing

Contributions to onboarding, workflow quality, tool portability, and evidence discipline are welcome.

1. Open an issue describing the problem using fictional or redacted examples.
2. Keep changes focused. Explain how the proposed workflow changes the user outcome.
3. Preserve final-version approval, deduplication, fact provenance, and local fallback behavior.
4. Update related documentation and examples. Check local Markdown links and JSON examples.
5. Do not commit private profiles, resumes, transcripts, contacts, holdings, credentials, account IDs, approval records, or copied paid research.

By submitting a contribution, you agree that your contribution is provided under this repository's MIT License. Do not contribute material you lack permission to share.
