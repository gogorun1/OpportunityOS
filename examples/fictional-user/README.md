# Fictional pilot: Alex

This example contains no real candidate, employer, contact, or application.

Alex is a junior product engineer seeking a six-month internship in an English-speaking team. They prefer workflow tools and have shipped a small scheduling prototype. Availability and work authorization remain unknown until Alex confirms them. Only Career is enabled; Investment and Startup are off.

## Example personalization

- Goal: identify a suitable junior product-engineering internship within three months.
- Strong-fit evidence: interface implementation, user interviews, API integrations, and documented iteration.
- Exclusions: senior-only roles, pure model research, and jobs requiring a working language Alex does not have.
- Channel: agent inbox, no email. A maximum of three decisions in a weekday digest.
- Pilot: research on Tuesday; Radar on Wednesday morning in Alex's confirmed timezone. Both tasks remain disabled until reviewed.

## Example completed result

**Agent Completed:** Compared one fictional junior Product Engineer role against Alex's confirmed project evidence and prepared a role-matching table.

**Thesis:** The tasks fit Alex's interface/API experience; academic eligibility and the start date remain unverified, so an application packet is not yet ready for submission.

**What You May Not Know:** The role's main responsibilities concern customer workflow integration rather than model training. Its AI title alone would have been a poor matching signal.

**Human Action:** Confirm the actual availability date and current enrollment status, facts only Alex can provide.

**Next Agent Task:** Verify whether the employer accepts the confirmed educational status and start date. Draft only after Alex selects the role.

**Archive:** One Research Brief and one role-selection signal, deduplicated by employer + role URL. No application is marked Submitted.

This demonstrates the output shape only. A real run must use verified employer sources, direct links, and actual candidate facts.
